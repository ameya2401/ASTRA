## Project

ASTRA (AST-Triage & Automated Risk Stratification for AI-Agent-Authored Pull Requests) is an automated triage and risk-scoring system that intercepts pull requests generated by AI coding agents (Devin, Claude Code, GitHub Copilot, OpenHands) before human review. It extracts structural AST metrics, NLP intent-to-diff semantic alignment, and process provenance features to predict PR risk using a calibrated XGBoost classifier with local SHAP explanations.

- Module: `ast-triage-core`
- GitHub repo: `https://github.com/ameya2401/ASTRA`
- Default branch: `main`
- Apps & engines:
  - FastAPI webhook receiver (`src.api.main:app`)
  - Tree-sitter AST structural differencing engine (`src/ast_engine/`)
  - Sentence-Transformers semantic alignment engine (`src/semantic_engine/`)
  - 28-D feature normalization & vector pipeline (`src/feature_pipeline/`)
  - Platt-calibrated XGBoost classifier + SHAP explainer (`src/ml_engine/`)
  - Async SQLite/PostgreSQL storage layer (`database/`)
- Architecture flow:
  `PR Ingestion` ➔ `AST Differ (F01-F12)` + `Semantic Drift (F13-F18)` + `Process Features (F19-F28)` ➔ `28-D Vector` ➔ `XGBoost + Platt Scaling` ➔ `SHAP Attribution` ➔ `GitHub PR Comment / Webhook Response`

## Todo protocol - response-only (mandatory)

1. **Create todos in the response before multi-step work.** On receiving any task (feature, bugfix, refactor, or multi-phase implementation), outline the plan as numbered todos in the response.
2. **Show current todos in responses.** Reflect current progress with status markers (`pending`, `in_progress`, `completed`) and clearly indicate which step is active.
3. **Do not store todos on disk.** Do not create `TODO.md`, `todos.json`, or temporary task files.
4. **Keep todos updated continuously.** Mark items complete as verified and update immediately if requirements shift.
5. **Completion requires verified gates.** A task is done only when all todos show completed and the corresponding verification gate commands pass.

## Golden rules

1. **No git push or destructive operations without user confirmation.** Do not run destructive git commands (`git reset --hard`, `git clean -fd`, `git push --force`) without explicit instruction.
2. **No em dashes ("--") in written docs or explanations.** Use commas, periods, or plain hyphens. Avoid robotic AI buzzwords ("leverage", "delve", "pivotal", "testament").
3. **Never commit secrets or generated artifacts.** Keep `.env`, `data/*.db`, `test_reports/`, `models/*.pt`, and `__pycache__` out of git. Strictly maintain `.gitignore`.
4. **Strict type hints and async discipline.** All core models use SQLAlchemy 2.0 mapped columns and Pydantic v2 schemas. Database sessions must use the `@asynccontextmanager` async session factory.
5. **Thread-safe singleton resources.** Heavy models (like SentenceEmbedder) must be initialized once via singletons protected with thread locks; never reload neural models in request loops.
6. **Error-tolerant AST parsing.** When processing PR diffs, use Tree-sitter's error-tolerant parser (`has_error` handling). Never allow a malformed syntax node from an agent PR to crash the triage service.

## Things to AVOID

1. **Do not use Python's built-in `ast` module.** All AST parsing must use `tree-sitter` and `tree-sitter-python` for cross-language compatibility.
2. **Do not reload models per request.** Loading MiniLM or XGBoost on every PR webhook introduces severe latency spikes. Use cached module-level singletons.
3. **Do not use raw line diffs for risk calculations.** Plain text diff line counts (`+10/-2`) are blind to AST structure; always compute structural node churn.
4. **Do not perform synchronous blocking I/O in FastAPI routes.** Always use async database sessions and async HTTP clients (`httpx`).
5. **Do not claim completion without running verification gates.** Always run and display the test output before claiming a task is done.
