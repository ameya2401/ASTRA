# Semantic NLP Features (F13 to F18)

> Implemented in [src/semantic_engine/drift_analyzer.py](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py) and [src/semantic_engine/embedder.py](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/embedder.py).

Semantic NLP features measure intent-to-diff alignment. They detect whether an agent actually addressed the user request or drifted into unrelated code areas.

---

## 1. Feature Specifications

### F13: `intent_diff_cosine`
- **Definition**: Cosine similarity between the dense embedding of the issue description and the embedding of the sanitized diff text.
- **Formula**:
  $$\text{Cosine}(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}$$
  where $u, v \in \mathbb{R}^{384}$ are generated by `all-MiniLM-L6-v2`.
- **Range**: $[-1.0, 1.0]$. A score above `0.65` indicates strong alignment. A score below `0.45` indicates strong risk of drift.
- **Code reference**: [src/semantic_engine/drift_analyzer.py:L112-L135](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L112-L135).

### F14: `title_diff_cosine`
- **Definition**: Cosine similarity between the PR/issue title embedding and the sanitized diff embedding.
- **Rationale**: Issue descriptions are often verbose or contain boilerplate logs. The title typically contains the concise core problem statement (such as "Fix connection pool timeout").
- **Code reference**: [src/semantic_engine/drift_analyzer.py:L285-L295](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L285-L295).

### F15: `entity_drift_jaccard`
- **Definition**: Jaccard distance between the set of code identifiers (variables, functions, classes) mentioned in the issue and the set of identifiers modified in the diff.
- **Formula**:
  $$J_{dist}(E_{issue}, E_{diff}) = 1.0 - \frac{|E_{issue} \cap E_{diff}|}{|E_{issue} \cup E_{diff}|}$$
  If both sets are empty, distance defaults to `0.0`. Standard Python language keywords (`if`, `for`, `def`, `self`, `return`, etc.) are stripped before set comparison.
- **Range**: $[0.0, 1.0]$. High distance means the code diff touches names completely absent from the ticket.
- **Code reference**: [src/semantic_engine/drift_analyzer.py:L170-L195](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L170-L195).

### F16: `docstring_code_ratio`
- **Definition**: Ratio of comment and docstring characters added in the diff to raw executable code characters added:
  $$\text{Ratio} = \frac{\text{len}(\text{added comments/docstrings})}{\max(1, \text{len}(\text{total added characters}))}$$
- **Rationale**: AI agents often generate massive multi-line comments explaining what they intended to do, or alternatively write pure uncommented blocks. Both extremes carry distinct risk profiles.
- **Code reference**: [src/semantic_engine/drift_analyzer.py:L200-L245](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L200-L245).

### F17: `semantic_drift_flag`
- **Definition**: Binary indicator set to 1 if `intent_diff_cosine` falls below the calibrated drift threshold of `0.45`, otherwise 0.
- **Triage Impact**: When `semantic_drift_flag == 1`, the triage policy automatically routes the PR to the RED risk band regardless of superficial structural cleanliness.
- **Code reference**: [src/semantic_engine/drift_analyzer.py:L27-L28](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L27-L28), [L310-L315](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L310-L315).

### F18: `issue_token_length`
- **Definition**: Approximate token count of the issue description, calculated as the whitespace-delimited word count.
- **Rationale**: Captures whether the prompt was underspecified (e.g. 5 words) or highly constrained (e.g. 800 words), which correlates with agent hallucination frequency.
- **Code reference**: [src/semantic_engine/drift_analyzer.py:L318-L322](file:///e:/study/ASTRA/ast-triage-core/src/semantic_engine/drift_analyzer.py#L318-L322).
