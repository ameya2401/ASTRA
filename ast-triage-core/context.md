## What is AST-Triage?

AST-Triage is an **automated risk-scoring system** designed to evaluate Pull Requests generated by AI coding agents (such as Devin, Claude Code, GitHub Copilot, OpenHands, etc.). It determines how likely a given PR is to be defective, misaligned with the original issue, or unsafe to merge — before a human reviewer even looks at it.

### The Problem It Solves

AI coding agents are increasingly generating pull requests autonomously. However, these PRs can contain:
- **Semantic drift** — the code doesn't actually solve the described issue
- **Test cheating** — deleted assertions or blanket try/except blocks that mask failures
- **Structural bloat** — excessive complexity changes without clear necessity
- **Scope creep** — touching files unrelated to the original task

AST-Triage catches these patterns automatically by analyzing the PR's code at three levels:

1. **Structural (AST):** Tree-sitter parses the syntax tree to detect cyclomatic complexity changes, node mutations, signature breaks
2. **Semantic (NLP):** Sentence-transformers compare the issue description against the actual diff to detect intent misalignment
3. **Statistical (ML):** A Platt-calibrated XGBoost classifier combines 28 engineered features into a single calibrated risk probability

## How the System Will Work (End-to-End)

```
GitHub PR Event → FastAPI Webhook → AST Parser → Semantic Embedder → Feature Vector (28-D) → XGBoost → Risk Score + SHAP → GitHub Comment
```

1. A GitHub webhook fires when an AI agent opens/syncs a PR
2. FastAPI ingests the PR payload (diff, issue description, metadata)
3. Tree-sitter parses pre/post code into ASTs and computes structural deltas
4. Sentence-transformers embed the issue and diff, computing cosine similarity
5. 28 features are assembled into a vector
6. XGBoost predicts a calibrated defect probability
7. SHAP explains the top 3 risk-driving features
8. A formatted risk report is posted back to the GitHub PR

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Database | SQLAlchemy 2.0 async + SQLite | Async for FastAPI compatibility; SQLite for zero-config dev, swappable to Postgres |
| Config | Pydantic BaseSettings | Type-safe, `.env` loading, validation at startup |
| AST Parsing | Tree-sitter (C bindings) | Fast, language-agnostic, production-grade syntax analysis |
| Embeddings | all-MiniLM-L6-v2 | 384-dim, fast inference, good quality for short-text similarity |
| Classifier | XGBoost + Platt calibration | Best-in-class for tabular data; calibration ensures probabilities are meaningful |
| Explainability | SHAP TreeExplainer | Local feature attribution — tells maintainers *why* a PR is risky |
